# დავალება: არსებული აპლიკაციის მედიკამენტების L5 ინდექსის ინტეგრაცია

მომხმარებლის არსებული აპლიკაცია განაახლე. ახალი საიტი არ შექმნა. ეს პატარა პაკეტი ჩაამატე ძველი 961 MB მედიკამენტების ZIP-ის ნაცვლად. უკვე არსებული კლინიკური/აკადემიის მასალა შეინარჩუნე. ჯერ დაათვალიერე რეპოზიტორია და არსებული მედიკამენტების მოძიების ყველა გზა.

## რას შეიცავს პაკეტი

FDA 2026-10-16 ჩამონატვირთის ყველა 262,897 label და 138,319 NDC ჩანაწერის ID, 580,114 სახელთან კავშირი; MIS-ის 29,591 უნიკალური კატალოგური ჩანაწერი, ქართული/ინგლისური სახელები და წყაროები. ყველა არსებული ინდექსური ჩანაწერი შენარჩუნებულია. ეს არ ნიშნავს მსოფლიოში ყველა წამლის დაფარვას. FDA-ს 179,225 label-ს წყაროში საძიებო სახელები არ აქვს; მათი ID შენარჩუნებულია, სახელები არ გამოგვიგონია. MIS არის სახელების კატალოგი, არა ყველა სრული ინსტრუქცია და არა დამტკიცებული ქართული რეგისტრაციის რეესტრი.

სრული კლინიკური ტექსტი ამ ვერსიაში ადგილობრივად არ ინახება. კონკრეტული ჩანაწერი FDA API-დან იტვირთება საჭიროებისას. სრული ოფლაინ არქივი მომხმარებელთან რჩება. არ დაამატო დიდ ZIP-ს ან clinical.pack-ს რეპოზიტორიაში, public-ში ან ფუნქციის პაკეტში.

## განთავსება და ზომა

1. პაკეტის `data/`, `manifest.json`, `casefold.json`, `store.mjs` გადაიტანე server-only საქაღალდეში, მაგალითად `knowledge/medications/`. data დაახლოებით 27.05 MB-ია. ეს არის დისკზე შესატანი ფაილების ჯამი, არა მხოლოდ ZIP-ის ზომა.
2. შეინარჩუნე `.json.gz` ფაილები შეკუმშულად. build-ის დროს მთლიანად არ გაშალო. runtime მხოლოდ მოთხოვნის შესაბამის მცირე ნაწილს შლის მეხსიერებაში. არ გააგზავნო მთელი ინდექსი ბრაუზერში ან მოდელის პრომპტში.
3. გამოიყენე Node.js runtime, არა Edge. ამ runtime-ს მესამე მხარის პაკეტები არ სჭირდება. Next.js-ში explicit outputFileTracingIncludes-ით მოიცავი `./knowledge/medications/data/**/*`, manifest და casefold საჭირო server route-ებისთვის. არსებულ next.config-ს დაუმატე და არ გადააწერო. ზუსტი კონფიგურაცია მოარგე რეპოზიტორიის ვერსიას.
4. გაზომე რეალური build/output/function ზომა. მომხმარებლის არსებული დაახლოებით 50 MB გაზომვა ვარაუდია; ამ პაკეტით სავარაუდოდ დაახლოებით 77 MB გამოვა. ფაქტობრივი deploy და მიმდინარე გეგმაზე მუშაობა მხოლოდ დასრულებული build/deploy შემოწმებით დადასტურდება.

## უსაფრთხო სახელის ამოცნობა და წყარო

- `await new MedicationStore().init()`; `lookup(query,{offset,limit})` აბრუნებს მხოლოდ ზუსტ კანდიდატებს, არა რეკომენდაციას. გვერდებად აჩვენე ყველა კანდიდატი. სტრიქონების მსგავსება, fuzzy search, ტრანსლიტერაცია და embeddings არ გამოიყენო წამლის ავტომატური არჩევისთვის. მსგავსი სახელები შეიძლება მხოლოდ დაუდასტურებელ საძიებო შეთავაზებად გამოჩნდეს.
- ყველა წამლის მოთხოვნა, მათ შორის აგენტის და სტუდენტის გვერდის მოთხოვნა, გაატარე ამ შემოწმებაში. LLM-მა თავისი მეხსიერებიდან არ შეავსოს უცნობი სახელის აქტიური ნივთიერება ან დოზა.
- `fetchCandidate(query,recordId)` მოაქვს ზუსტ ID-ზე მიბმული წყარო პროდუქტის გადამოწმებისთვის. ეს ფუნქცია server-only იყოს; გადამოწმებამდე UI-ს მიეცი მხოლოდ იდენტობის ველები: დასახელება, ინგრედიენტი/მარილი, დოზის სიძლიერე, ფორმა, შეყვანის გზა, მწარმოებელი და წყაროს ID. სრული ტექსტი/დოზები არ გადასცე აგენტს ამ ეტაპზე.
- მომხმარებელი/უფლებამოსილი კურატორი ადასტურებს კონკრეტულ პროდუქტს. backend ქმნის მოკლევადიან შემთხვევით token-ს და ინახავს სესიაზე მიბმულ receipt-ს: `record_id`, `query_normalized`, `content_sha256` (fetchCandidate-დან), `expires_at` (epoch milliseconds). შემოწმდეს აქტიური ნივთიერება/მარილი, ფორმა, სიძლიერე და გზა. არასაკმარისი ველები ნიშნავს დაუდასტურებელ პროდუქტს.
- constructor-ის `resolveConfirmation(token)` უნდა კითხულობდეს მხოლოდ backend-ის სანდო სესიას/საცავს; ის არ უნდა ენდობოდეს მოთხოვნაში ან მოდელის tool call-ში გამოგზავნილ boolean-ს ან receipt-ს. default ყველა დადასტურებას უარყოფს. `context()` თავიდან ამოწმებს წყაროს ID-ს, ჯგუფს, სახელსა და შიგთავსის hash-ს. შეცვლილი წყარო მოითხოვს ახალ დადასტურებას.
- `allow_instruction_generation:false` განზრახ რჩება: იდენტობის დადასტურება არ ნიშნავს კლინიკური დანიშნულების ავტომატურ დამტკიცებას. აპლიკაციის ცალკე კლინიკური წესები და ადამიანური კონტროლი საჭიროა. პაკეტი მოდელს არ წვრთნის; ეს არის მოძიების ცოდნის ბაზა.
- `data/unapproved-crosswalk.json.gz` მხოლოდ კურატორისთვისაა. ყველა ქართული-ინგლისური FDA კანდიდატი დაუმტკიცებელია. მხოლოდ სახელის დამთხვევით ქართულ ბრენდს FDA პროდუქტი არ მიაბა. MIS-only წამლის შემთხვევაში აჩვენე: „დასახელება კატალოგში მოიძებნა; დადასტურებული ინსტრუქცია ჯერ არ არის დაკავშირებული“ და წყაროს ბმული.
- კოლომიცინი/Colomycin არ არის colchicine/კოლხიცინი. MIS evidence-ს Colistin ჯგუფი არ გამოიყენო მარილის/ფორმის ავტომატურ დასადგენად. არ შეაერთო colistin და colistimethate sodium სხვადასხვა პროდუქტის დოზები. IU/mg გადაყვანა ამ ინდექსით აკრძალულია.
- NDC ჩანაწერი შეიცავს პროდუქტის მონაცემებს, მაგრამ თავისთავად სრული ინსტრუქცია არ არის (`clinical_text_available:false`). საჭირო label-ს დაუკავშირე მხოლოდ NDC წყაროს `openfda.spl_set_id`-ით: label endpoint-ზე set_id-ის ზუსტი ძიება, ყველა პასუხის set_id შემოწმება და არჩეული პროდუქტის ინგრედიენტის/ფორმის/გზის შესაბამისობის დადასტურება. არ ჩათვალო მხოლოდ იგივე დასახელება საკმარისად. ეს დამატებითი დაკავშირება საცნობარო runtime-ში ავტომატურად არ სრულდება; მის გარეშე NDC დოზირების პასუხი არ გასცე.

## API და მუშაობის შეზღუდვები

FDA-სთვის `OPENFDA_API_KEY` შეინახე მხოლოდ server environment-ში. საიდუმლო არ ჩაწერო კოდში/ბრაუზერში/ლოგებში. ოფიციალური გვერდი მიუთითებს: გასაღების გარეშე 1,000 მოთხოვნა/დღე/IP; გასაღებით 120,000/დღე და 240/წუთი. გადაამოწმე ინტეგრაციისას. ერთი პროდუქტის preview/context შეიძლება ორ მოთხოვნას მოითხოვდეს.

runtime-ს აქვს 12-წამიანი timeout, პასუხის 8 MB ზღვარი, ფიქსირებული HTTPS host, ID/group/name შემოწმება. 404/429/timeout/მიუწვდომელი ან შეცვლილი წყარო ნიშნავს „ინსტრუქცია დროებით მიუწვდომელია“, არა სხვა პრეპარატით ჩანაცვლებას. დაამატე server rate limiting, მოთხოვნების გაერთიანება და ზომით შეზღუდული cache. cache მიაბი source ID-ს, შიგთავსის hash-ს, გადამოწმების დროსა და TTL-ს. expiry-ისას თავიდან გადაამოწმე; მუდმივ მეხსიერებას serverless-ზე ნუ დაეყრდნობი. სრული API პასუხი არ დაუბრუნო ბრაუზერს: საჭირო სექციები გვერდებად მიაწოდე, მაგალითად მაქსიმუმ 250 KB თითო პასუხზე.

## სტუდენტის გვერდი

არსებულ დიზაინს მოარგე მოკლე ბარათები და დაწკაპებით გასახსნელი სექციები. ჯერ საძიებო შედეგი/პროდუქტის ზუსტი არჩევანი, მერე დადასტურებული წყაროს სექციები. აჩვენე წყარო, მისი თარიღი და გადამოწმების სტატუსი. ქართული თარგმანი მონიშნე როგორც თარგმანი; ორიგინალი ხელმისაწვდომი იყოს. თარგმანის მოდელმა წამლის სახელი, სიძლიერე და ერთეული თვითნებურად არ შეცვალოს. უცნობი ან დაუდასტურებელი პროდუქტისთვის დოზირების ბარათი არ შექმნა.

## ჩაბარების შემოწმება

გაუშვი `node test.mjs`; საჭიროებისას `node live-test.mjs`. `qa-coverage.json` ადასტურებს სრული ინდექსის თანასწორობას ძველ პაკეტთან. დაამატე აპლიკაციის ინტეგრაციული ტესტი: „კოლომიცინი“ ვერ აჩვენებს colchicine ტექსტს, უცნობი/შეცდომით დაწერილი სახელი არ იცვლება სხვა წამლით, დაუდასტურებელი ქართული შესაბამისობა არ იძლევა დოზას, FDA-ის გათიშვა არ იწვევს მოდელის გამოგონილ პასუხს. ასევე შეამოწმე pagination, მობილური UI, source ცვლილება, ყალბი confirmation token და response ზომა. არ განაცხადო, რომ სამედიცინო შეცდომა შეუძლებელია. ჩააბარე ცვლილებები და გაზომილი ზომები; deployment გააკეთე მხოლოდ მომხმარებლის შესაბამისი ავტორიზაციით.
